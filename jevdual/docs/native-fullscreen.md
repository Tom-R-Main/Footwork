# Native fullscreen preparation

`look` can offer `Enter Full Screen` or `Exit Full Screen` under `Native window`. Use its fresh observed ID (`-2`, a native semantic action ID, not an SDK index) with the existing `do click ID` command, or the exact offered label. Partial labels, extra arguments, non-click operations, drag endpoints and agent/System 1 dispatch are refused. This opt-in operator route requires a foreground-permitted posture or exclusive desktop custody; filmed sessions refuse this preparation.

The control must be the exact bound PID/window's unique direct `AXFullScreenButton`, enabled, advertising `AXPress`, with an observable `AXFullScreen` boolean. The native title-bar census preserves AX read errors: an unsupported/absent optional subrole is distinct from an unreadable peer, which refuses. Other anonymous SDK controls remain excluded. The semantic candidate has no SDK token or pointer frame; geometry never associates it with an SDK element. A fixed-purpose internal AX adapter requalifies the same native references and expected state and performs only AXPress. No new generic AX/action/token endpoint, pointer-coordinate fallback, title-bar click, shortcut, first-match menu behavior, controller or helper is exposed.

The session persists `native_window_control`: `pid`, `window_id`, `subrole`, `window_hash`, `button_hash`, and `fullscreen`. Across commands this proves fresh exact-window semantic qualification, not uninterrupted object identity. CFHash is an additional conservative discriminator, not unique global identity; same-hash replacement may qualify the same semantic action anew. During one action actual AX references are retained and checked across foreground preparation and immediately before the press. App-side state can still change between the final read and handling AXPress; no atomic compare-and-toggle primitive is claimed.

The action retains version1 `native_readback`, producer `footwork.ax.fullscreen`, predicate `native_fullscreen_state_transition`, `before`, `after`, `press_acknowledged`, and `transition_observed`, with an optional error. Only an acknowledged press plus an independently observed state transition confirms the effect. Ordinary and durable receipts enforce the same predicate; the durable validator additionally binds the admitted click, target, process/window, dispatch, count and effect. An acknowledgement alone, visual label change, or changed state after an unacknowledged press cannot confirm. Unknown evidence cannot be relabeled as menu or insertion evidence.

Successful state reads poll for at most two seconds. An unreadable/replaced window stops readback immediately, retains uncertainty and never repeats the press. `after.bounds` is the observed native window frame or null when unavailable. No automatic window-ID rebinding occurs. A fullscreen transition that replaces the window therefore requires reconciliation.

Fixture qualification does not establish live fullscreen behavior or production framing. Live preparation remains held until reviewed installed delivery, followed by exact runtime/window identity, normal custody and actual fullscreen/client/content measurements. Existing duplicate menu paths continue to refuse.
