# D3: six visual task families with captured observations and execution checks

Registered before implementation and measurement. Scope: the six recommended families from the twenty-task catalog. Development pilot with authored controlled fixtures, not independent adoption validation. Existing $5 combined pilot ceiling and credentials; no runtime routing/settings changes or sealed cases.

## Hypothesis and primary metric

Bounded visual proposal judgments improve confident correctness where normal DOM/AX text loses visual evidence, while retaining abstention on ambiguous inputs. Primary: number of cases correctly judged in all three replays, comparing Decisions combined pixels+observed text against Decisions observed text. Jev observed text is the active-backend comparator. Native predicate bands remain true>=.80, false<=.20, otherwise unknown; ambiguous labels require unknown or explicit refusal (reported separately).

Guardrail: no confidently true invalid proposal or completion, and no wrong effect dispatched. Against the hypothesis: no combined gain, any invalid confident acceptance, or apparent gain requiring an oracle label or deliberately suppressed available accessible evidence. This is a development qualification rule, not a calibration guarantee.

## Cases and surfaces

Six families: toolbar glyph proposal, map marker containment, scanned document identity, crop boundary preserving subject, export at 100% while finalizing, target changed after capture. Four variants each: supported proposal, near-miss invalid proposal, underdetermined/ambiguous state, and accessible text-rich control. Total 24 cases x three provider/evidence arms x three replays =216 scheduled judgments. Distinguish browser controlled fixtures and native app/fixture captures. Native routes must be demonstrated; if unavailable preserve concrete access evidence, do not silently count a browser imitation as native coverage. No screenshots of unrelated apps or user data. Fixture setup writes only within the active project; run-owned processes only.

Case question asks whether one explicitly offered bounded proposal is supported by the current evidence. No invented coordinates or arbitrary arguments: execution uses captured target IDs/bounds plus deterministic task geometry/resource identity. Keep semantic judgment separate from deterministic admissibility. Freshness and actual persisted export cannot be established from a screenshot alone. Provide current/previous observations explicitly for temporal cases, and record both native semantic and final guarded results.

Use standard accessible names/roles/values/states, rendered text and bounds from the actual browser/native observation without hiding useful labels. Local OCR may supplement native raster documents where runtime access permits; record source and completeness. Exclude hidden JS/oracle state and answer-bearing filenames from model inputs. Images capture actual fixture rendering; no model output changes fixtures or labels. Text-rich control exposes ordinary accessible content, not expected boolean labels. Capture bound surface/process/window, timestamps, revision and image SHA256; native images and screenshots are not invented for unavailable routes.

## Outcomes and timing

Freeze source, case manifest, independent oracle and harness before paid calls; clean named commit and fresh directories. Capture receipt for each case, with code-authored truth retained only in evaluation metadata. Verify icons by actual mode state, map selection by point-in-polygon geometry, document identity by immutable source hash/identity, crops by saved rectangle/subject geometry, exports by completed readable artifact, stale targets by refusal/no dispatch then fresh-binding behavior. Controlled native fixture substitutes must be named explicitly; they do not establish Finder/Preview acceptance.

Capture browser/app observations on real running surfaces. Replay captured evidence for matched sequential randomized model calls, seed10082028, pooled clients, no automatic retries, three repeats. For unambiguous native/browser proposals at the frozen bands, dispatch through a freshly observed run-owned target only after deterministic scope/freshness/geometry/resource checks; independently read the postcondition. For ambiguous/refused/invalid/unknown/stale proposals, do not dispatch. A scripted ground-truth trajectory first establishes that each intended effect is actually executable and each negative guard rejects; that is harness conformance, not model quality. Record any missing execution path as unverified, never as success.

Report capture/extraction/OCR/encoding, request/parsing, replay/validation, dispatch/readback and total wall phases. Captured-evidence request replay is not a live-loop latency claim: capture-to-judgment estimate adds measured capture phase to each request, and actual execution phase is measured separately. Record polling/setup delays, all errors and cold calls. Quantify all-three correctness, invalid confident positives, ambiguous abstention, useful positives, final outcomes and median/p95 timing by arm/surface/family. Every attempt retains native model, p, refusal/error, usage and request/evidence hashes. Actual surface errors are coverage failures, not model correctness failures.
