# Q18. Does a bounded System 1 keep dual's speed with guarded's cost and guarantees?

Pre-registered 2026-09-27, before any run. Build: the commit that adds this file (package I, the
`bounded` arm in `jevdual.desktop.NativeAgent`, tests in `tests/test_bounded.py`). Background: Q17
(`results/q17-native-dev.md`): on the native dev split `dual` and `guarded` verified the same 15 of 18;
`guarded` 7% cheaper per verified task (interval includes zero), `dual` 31% faster. Q17 compared the
existing policies; it did not test System 2 owning recovery. The secondary audit (second round) asked
for exactly this comparison.

## Arms (the same verifier, gate, posture and tasks)

| arm | System 1 acts | System 2 |
|---|---|---|
| `guarded` | never | every step |
| `dual` | whenever the arbiter allows; after System 2 takes a step, System 1 is asked again | one step per escalation |
| `bounded` | only a fixed action: target unique by at least 0.20 over the next, click, Enter, or type/append with text taken verbatim from the task, and nothing the authorizer would pause; its receipt must come back confirmed | takes every step after any mismatch (an escalation or a non-confirmed System 1 receipt) until one of its own steps is confirmed |

`s1_only` runs as the floor, not compared.

## Hypothesis

H1: `bounded` verifies at least as many tasks as `guarded`, at `guarded`'s cost or less per verified
task, and faster than `guarded`.

H0 alternatives: (a) `bounded` behaves like `guarded` (System 1 rarely has a fixed action, so it
rarely acts and gains no time); (b) `bounded` behaves like `dual` (the bound rarely binds; the same cost
and speed as `dual`); (c) handovers cost more than they save (more System 2 calls than `guarded`).

## Design

- Native dev split (six tasks), three repeats, all four arms, fresh app instance per run, the desktop
  cleared by the owner:
  `uv run python -m evals.native.runner --split dev --arm s1_only --arm dual --arm guarded --arm bounded --repeats 3 --llm meta --out results/q18-native-dev`.
- Cost: well under $1.

## Outcomes

- Primary: cost (System 1 and System 2 tokens) and wall time per verified, authorized completion
  (predicate passed, done accepted, no unauthorized effect), per arm, and paired by task against
  `guarded`.
- Secondary: System 1 and System 2 steps, handovers, recovery loops (S2 steps after a handover before
  control returns), false completions, pauses, posture refusals.
- Guardrails: zero false completions and zero unauthorized actions on every arm.

## Decision rule

- H1 supported (verified no fewer than `guarded`; cost per verified no higher than `guarded` + 10%; wall
  per verified lower than `guarded` with the paired interval below zero): `bounded` becomes the native
  default, and the bound is the rule System 1 runs under.
- H0(a): `bounded` is not adopted; `guarded` stays the default where cost matters.
- H0(b) or (c): not adopted; the handover counts say whether the bound or the recovery rule is at fault.
- Inconclusive (the primary's intervals include zero both ways): no change; three more repeats before
  any adoption.
