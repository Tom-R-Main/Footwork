# Q10. Does the arbiter's calibration transfer from DOM menus to accessibility-tree menus?

Pre-registered 2026-09-24, before any measured run on the native split. Build: commits 3fadd7e,
9163e79, c85647d and the P3 commit (native menu builder, NativeAgent, NativeS2, native runner).
Plan: `docs/plans/native-computer-use.md`. Survey: `docs/cua-notes.md`.

## Observation

The dual-process loop now runs on native macOS windows through Cua Driver with the browser
policy, prompts, arbiter thresholds (`arbiter.toml`), verifier and trace unchanged. Only the
menu builder is new: candidates come from the accessibility tree (role, label, value, enabled,
selected, section from labelled ancestors), page text is the window's static text plus text-field
values, and there is no `href`. Spikes (`results/native-spike-20260924/`) showed System 1 driving
Calculator and TextEdit at target confidence 0.52 to 1.00 with the same floors, and the verifier
accepting a typed sentence at complete 0.97. The oracle solvers pass 7/7 on the dev split
(`results/native-oracle-20260924/`).

On the web, Q1 found target confidence AUROC 0.80 on clicks and operation confidence 0.59
overall; the arbiter's floors are 0.55 (operation) and 0.45 (target).

## Hypothesis

H1: the calibration transfers. On native menus, System 1's target confidence predicts a right
click about as well as on the web (AUROC within 0.10 of 0.80 on labelled click rows), the
arbiter's floors give a false-escalation rate at or below the web's, and `dual` completes at
least as many dev tasks as `guarded` at lower cost per completion.

H0 alternatives: (a) confidence is flat or inverted on native menus because the signals that
carried it on the web (`href`, section names, page text) are absent; (b) System 1 completes the
clicks but the verifier cannot accept native end states (window text is too thin), so `dual`
loses to `guarded` on verified completions rather than on steps.

## Predictions

If H1 is true:
- `s1_only` passes at least 4 of the 7 dev tasks (the click-only Calculator tasks and the typing
  task); the two answer tasks fail by design (System 1 cannot compose an answer).
- `dual` passes at least as many as `guarded`, with fewer LLM calls per task.
- On the labelled S1 rows, target-confidence AUROC on clicks is at least 0.70 and the operating
  point at the current floors escalates no more than 20% of right steps.
- The verifier accepts the oracle end state of every non-answer task when asked directly.

If H1 is false:
- (a) AUROC on clicks below 0.65, or `s1_only` under 3 passes with escalations dominated by
  `target_confidence`.
- (b) `s1_only` steps reach the end state (predicate passes) but `is_done` stays false because
  every `done` is refused; `guarded` completes what `dual` does not, at higher cost.

## Design

- Split: `evals/native/tasks/dev.yaml` (7 tasks: 4 Calculator, 3 TextEdit; 2 answer tasks) with
  every oracle passing before the run. Tranche 2 (consent classes: Save over an existing file,
  Move to Trash, Delete; Finder, Dictionary, Preview, System Settings read-only, one Electron
  probe) is added by amendment before it is measured; nothing in tranche 1 is changed after.
- Arms: `s1_only`, `dual`, `guarded`. Three repeats per arm, same task order, one app at a time,
  fresh app instance per run.
- System 1: Jev 1.13 through `JevPolicy`, unchanged prompts (`PROMPTS_VERSION` in the header).
  System 2: Muse Spark 1.3 Contributor, `reasoning_effort=low`, 4000-token budget, the closed
  native action set. Verifier: the same `Verifier` and bands as the browser track.
- Labels: the Q1 protocol (two blinded Fable passes over blinded packets, agreed `model_label`,
  human audit of 40 rows) on every S1 decision row of the three arms, then `evals.calibration`.
- Runner: `uv run python -m evals.native.runner --split dev --arm s1_only --arm dual --arm guarded --repeats 3`.

## Primary metric and guardrails

Primary: verified completions per arm (predicate passed and `is_done`), paired by task across
arms with bootstrap 95% intervals on the difference (counts, not percentages, at n = 7).

Guardrails: crashes (launch failures, Driver refusals that end a run); false completions (a
claimed done whose predicate fails); paused runs on tranche 1 (there are no consent tasks, so any
pause is a false pause); estimated cost per verified completion.

Secondary: target-confidence AUROC on labelled click rows; false-escalation rate at the current
floors; per-step Driver effect words (share of `unverifiable`, `refused`).

## Decision rule

- H1 supported (all three: `dual` ≥ `guarded` on verified completions, AUROC ≥ 0.70, false
  escalation ≤ 20%): the native backend joins the default configuration with the browser
  thresholds; tranche 2 is pre-registered as an amendment and the consent gate is measured
  there before anything native is called safe.
- H0(a): the menu builder is the variable. Next experiment adds section and static-text context
  per candidate and re-measures; thresholds are not tuned on this split.
- H0(b): the verifier is the variable. Native end-state text gains structured fields (window
  title, focused control, dialog text) before re-measuring; System 2 is not made the default.
- Inconclusive (intervals cross zero and AUROC between 0.65 and 0.70): tranche 2 first, then
  re-decide on the pooled rows.
