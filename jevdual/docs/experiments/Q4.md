# Q4. Per-step arbitration or per-subgoal delegation?

Status: pre-registered 2026-09-21. Depends on the Q6 multistep tasks and arm configurations.

## Observation

S1 gets first shot every step; `act_toward_goal` lets System 2 delegate a subgoal but nothing
encourages it. Role-factorised search agents found capacity matters at the delegation role while a
small executor matches a frontier model at fewer tokens [H8]; planner-executor designs with explicit
pre- and post-conditions generalise across sites [H2] and train better with per-subgoal credit
[H5][H12]. Two studies disagree on where web agents fail: low-level execution [H1] versus planning
[H7].

## Hypothesis

On tasks with three or more dependent subgoals, System 2 delegating post-condition-checked
subgoals to S1 uses at most 70% of the LLM calls of per-step arbitration, with pass rate within the
paired interval.

## Predictions

If true: LLM calls(delegation) ≤ 0.7 × LLM calls(per-step); pass-rate difference interval includes 0.

If false: pass rate drops more than 5 points, or LLM calls do not fall below 85%.

## Design

Tasks tagged `multistep` in `live-dev` (URL checkpoints define the subgoals). Arms: per-step
arbitration (current default) versus delegation (System 2 prompted to call `act_toward_goal` with
a post-condition per subgoal; S1 runs the subgoal until the post-condition noul passes or the
budget ends). Three repeats. Primary metric: LLM calls per task. Guardrails: pass rate; checkpoint
coverage; false completions.

Secondary read-out: which side of the planning-versus-execution disagreement these tasks fall on,
from where delegation runs fail (subgoal chosen wrongly versus subgoal executed wrongly).

## Decision rule

Supported: delegation becomes the default on tasks the planner judges multistep. Falsified:
per-step stays; the tool remains available. Mixed by task length: the boundary is set at the length
where the interval crosses zero, and recorded.
