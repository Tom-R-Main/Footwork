# A2: journal-validated operation reports, then local packaging

User authorized validating host completion reports against durable operation state, then packaging. A1 remains failed7/8 answer acceptance; its original data is unchanged.

## Mechanism and scope

Add a read-only report tool and Python validator. Hosts return a structured report: completion (completed/not_completed/unknown), every admitted operation ID with its claimed disposition, and disk persistence (not_checked/saved/unsaved). Validation reads the full task operation ledger, including records older than status's ten-row recent projection. Completed requires at least one operation, all final/applied and no omitted or unresolved records. Unknown/dispatching takes precedence. Known non-applied outcomes and zero operations cannot be completed. Claimed IDs/dispositions/completion must match; saved or unsaved assertions are unsupported and rejected. This conservative report covers all admitted operations in the configured task, not the host's broader job, future intentions or arbitrary prose. Known failed attempts remain visible; a higher-level host may explain them separately without this validator certifying its job.

Reports never dispatch, launch a worker, reconcile from text or alter an operation. A qualified receipt must first be collected through status to change history. Current document content and persistence are not certified by this historical report; later external edits cannot erase historical applied. Emit a deterministic trusted summary from actual ledger state, even when the model report is rejected. A host adapter publishes only that summary. Arbitrary unvalidated model prose is retained as evidence and never treated as approved text. Unavailable/invalid journal or validation fails closed; no fallback to the host's completion assertion. Reports include task, exact snapshot digest and as-of time, with no promise of future validity or malicious same-user containment.

MCP adds report while preserving bind/observe/act/status. CLI validation reads the existing private journal in SQLite read-only mode from trusted startup paths; report JSON cannot choose another task/journal. Include bounds and owner/path/mode/schema checks, consistent full-ledger snapshot, strict nested argument validation, cross-task/duplicate/omission refusal and explicit unavailable-state output. No raw operation payload or field text is needed in report output.

## Qualification

Primary criterion: zero trusted completed summaries for an unknown, dispatching, omitted, malformed, foreign, stale or unchecked-persistence report. Positive applied reports remain usable. Deterministic public MCP/CLI tests exercise over-ten-row omission, zero operations, known failures, repeated validation with no journal change, live-owner readonly access and restart/receipt history. Replay A1's actual Codex unknown report against its retained journal without modifying it. Then freeze code and run four fresh Codex structured-output sessions through the same native cases and ordinary task, with adapter validation after host closeout. Count raw model answers separately from validated published output; do not regrade A1. Existing installed CLI/default model is used; record observed limits and token accounting. No additional Claude paid CLI review. Carry prior Claude cost0.548364USD; this phase schedules only Codex subscription CLI trials. Actual native oracle, worker custody, catalog restart and cleanup remain required. Invalid harness/session stops, with failures retained.

Packaging begins after deterministic/native adapter gate qualifies. Build an offline pure-Python wheel with optional existing Rust acceleration preserved, explicit MCP dependency, actual MIT source/license and bounded file manifest. No research/heldout/results/secrets/build caches ship. Provide CLI server/report/doctor/config entry points and host examples. Verify ZIP metadata/hash records, install offline into a clean owned target, run outside the checkout with installed-first imports, initialize/list tools/status/report and qualify detached worker module discovery on a supported macOS fixture. Diagnose permission/dependency/platform/scope gaps without requesting OS grants, changing global host config or fetching dependencies. Keep pinned driver/model roles and old session CLI dependency expectations. This produces local reviewable distribution artifacts, not PyPI publication or a general app/platform release.

## Decision

Only journal-validated published output is measured as safe; a model calling report or seeing clearer prose alone cannot enforce its final answer. If that boundary qualifies, package it and document the required host adapter. If unsafe completion survives the trusted renderer, stop packaging until the defect is resolved. Broad job completion, saved-file persistence, arbitrary apps, network installation, push/merge and public publication remain separate.
