# Core readiness before Suno Studio

November 11, 2026. User clarification explicitly includes Suno Studio, with a reference screenshot of Studio 1.2 at studio-legacy. The prior bounded Legacy Song Editor package remains historical evidence and does not complete this scope.

Hypothesis: after addressing demonstrated core defects from the preceding tranche, the public guarded Footwork route can perform a bounded Studio track or clip change, export its actual audio, and retain that change after project reopen.

Predicts if true: actual project identity, initial and changed values, one intended change, decodable project-local audio and retained project state can be independently reconciled without private input helpers, guard relaxation or modifying published reference songs.

Predicts if false: a necessary Studio operation lacks qualified targeting, delivery, readable state, artifact verification or persistence evidence. A menu opening or an offline suite alone cannot count as completion.

Design: prioritize a read-only review of unresolved core issues; reproduce driving defects through the public CLI simulator before repairs. Use immutable source per live phase, exact actual native window binding, fresh observations and one UI owner. Inspect the user's actual Studio version before selecting an operation. Work only on run-owned test resources. Prefer a reversible measurable track change over an arbitrary canvas action. Export only inside the project; compare decoded media and reopen the saved project. Preserve failure evidence and amend before a new paid perception experiment.

Primary metric: evidenced milestones completed out of four: identified Studio project and source; bounded changed state; independently verified audio artifact; retained state after reopen. Also report core defects repaired and unresolved prerequisites without combining them into a reliability rate.

Guardrails: no purchase, publication, repeated generation/unlock after unknown outcomes, arbitrary coordinates, posture widening, global installation, secret disclosure or fallback provider. Existing task authorization covers bounded test edits and the selected OpenRouter route; this experiment does not silently extend the closed media-call protocol.

Decision rule: complete only when all four milestones have actual evidence. If the route exposes a core defect, pause dependent UI work and repair it first. If a required capability needs additional user authorization, prepare a concrete reviewable implementation and explain that specific requirement.
