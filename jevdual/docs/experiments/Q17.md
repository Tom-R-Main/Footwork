# Q17. Who should own recovery on the native path: System 2 alone, or System 1 with System 2 behind it?

Pre-registered 2026-09-26, before any run. Plan: `docs/plans/next-work.md` (E, second bullet).
Background: Q10b (`results/q10b-native-dev.md`), Q9 (`results/q9-live-dev.md`).

## Observation

Two readings of the same numbers have driven the design. Q10b run 2, 18 runs per arm: `dual` (System 1
acts, System 2 repairs on escalation) made 44 System 2 calls against `guarded`'s 130 (System 2 alone),
which reads as "System 1 saves System 2 work"; it also cost 29% more ($0.032 against $0.025) and
verified two fewer tasks (13 against 15). On the browser, Q9 found the same order per verified pass:
`guarded` $0.0100, `dual` $0.0117, `delegate` $0.0137. Call counts reward handing work to the cheaper
model; what the person pays for is a correct, authorized task, in money and in time.

## Hypothesis

H1: per correctly completed, authorized task, `guarded` (System 2 owns every step and every repair) is
cheaper and no slower than `dual` on the native dev split.

H0 alternatives: (a) `dual` is cheaper per verified task once its System 1 steps are counted at their
real token cost, because Calculator and TextEdit are mostly mechanical; (b) the two are within 10% on
cost and the difference is latency, where `dual`'s fast System 1 steps win.

## Arms

| arm | who acts | who repairs |
|---|---|---|
| `guarded` | System 2 | System 2 |
| `dual` | System 1 when the arbiter lets it | System 2 on escalation |

`s1_only` runs as the floor, not compared.

## Predictions

Pooled over three repeats of the seven-task native dev split, paired by task:

- If H1: cost per verified completion lower on `guarded` with the paired interval on cost per task
  excluding zero in its favour; wall time per verified completion not higher by more than 10%.
- H0(a): `dual`'s cost per verified completion lower.
- H0(b): cost within 10%, `dual` faster by more than 10%.

## Design

- Runner: `uv run python -m evals.native.runner --split dev --arm s1_only --arm dual --arm guarded
  --repeats 3 --out results/q17-native-dev`, fresh app instance per run, Calculator in Basic mode.
- The native runner takes the desktop (`exclusive_desktop`): it runs only when the owner has cleared
  the Mac. This is why the run is held after pre-registration.

## Primary metric and guardrails

Primary: cost in USD per verified completion (predicate passed and done accepted), System 1 and System
2 tokens both counted, per arm; paired per-task cost with its bootstrap interval. Beside it: wall
seconds per verified completion, System 2 calls (the old reading, reported, not decided on).

Guardrails: zero false completions and zero unauthorized actions on both arms; a posture refusal
(`requires_foreground`, `human_active`) is reported as its own outcome, never retried silently.

## Decision rule

- H1 supported: System 2 owns recovery on the native path; System 1's role there is the verifier and
  the destructive judgment, and `dual` is no longer the native default.
- H0(a): `dual` stays and the plan's rule (System 1 finishes only mechanical actions whose target,
  arguments, permission and expected effect are fixed) is built and measured next against it.
- H0(b): the choice is the person's to make per task (money against time), and both stay.

## Result (2026-09-26)

`results/q17-native-dev.md`: H0(b). Both arms verified 15 of 18; `guarded` 7% cheaper per verified
task with the paired cost interval including zero, `dual` 31% faster with the interval excluding zero.
Both stay; the choice is money against time. Every failure on both arms is `textedit-append-line`,
correct work the verifier would not accept.
