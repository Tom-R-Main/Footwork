# Q2. Should the check sit before the action or after it?

Status: pre-registered 2026-09-21. Depends on the Q6 task set and arm configurations.

## Observation

The arbiter judges before dispatch (confidence floors, nouls, keyword gate); the effects diff
and done-verification judge after. Hierarchical monitoring pairs a cheap fast consistency check
with a selectively triggered slow monitor [A17]; GUI agents that verify an action's effect before
continuing recover from failure loops far better [V20].

## Hypothesis

Post-action checks (did the page change as the operation implied; is the done supported) prevent
at least as many failures per dollar as pre-action confidence gating.

## Predictions

If true: failures prevented per dollar (relative to an arm with neither) is ≥ for post-only than
pre-only, with the paired interval excluding a pre-only advantage.

If false: pre-only prevents more failures per dollar, or post-only breaches the false-completion
guardrail (more claimed-done predicate failures than pre-only).

## Design

Three dual-arm configurations on `live-dev`, three repeats: pre-action rules only (arbiter floors
and nouls, no effects diff, no done verification); post-action only (always act on S1's proposal,
effects diff and verification on); both (current default). The destructive gate stays on in every
arm; it is a safety property, not an experimental variable. A fourth arm with neither gives the
failure baseline.

Primary metric: failures prevented per dollar versus the neither arm. Guardrails: false
completions; crashes; wall time.

## Decision rule

Keep the rules that earn their keep: any rule class whose removal changes neither pass rate nor
false completions beyond the interval is retired from the default.
