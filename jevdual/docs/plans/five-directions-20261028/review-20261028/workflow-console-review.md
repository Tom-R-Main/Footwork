## Ranked findings and required changes

1. **High: expected bytes alone do not establish the intended saved document.** D5 correctly identifies the missing task oracle, but the current `save_readback` intentionally checks window text against decoded disk text (`python/jevdual/native.py:1312–1343`). It is not inherently wrong for that narrow claim. The overclaim occurs when this becomes task success. It follows the current AXDocument path, uses universal-newline decoding, and has no bound expected content/path argument. Worse, completion checks only the basename against a window-title-derived document (`completion.py:123–134`; `session.py:1235`). Equal content in another directory can therefore escape this identity limit; this is a source-only inference, not a reproduced failure.

   Bind expected bytes/digest, absolute destination identity, and append operation before save. Require fresh window equality and identity immediately before dispatch and qualified file readback afterward. Keep window/disk agreement as a distinct legacy basis; never silently upgrade it to intended-task correctness. Include same-basename/wrong-directory, wrong-window/same-content, CRLF/LF, Unicode, missing file and conflicting edit cases.

2. **High: the proposed filesystem guarantee exceeds the existing oracle.** B:72 describes `read_regular` as “no symlinks, change-detected.” It rejects the final symlink and checks metadata on the opened descriptor (`artifacts.py:19–39`); it does not forbid symlinked parents or detect a pathname replaced after opening. `check_artifact` verifies digest-bound equality, explicitly without session provenance (`artifacts.py:1,42–65`). Reuse it, but specify the allowed directory/path policy and time of the claim. Do not promise an atomic transaction across AX, filesystem and journal. Preserve safe-save inode replacement (`capability/recovery.py:161–163`). The fixture's descriptor/path recheck is a useful existing pattern (`scripts/capability_fixture.py:355–363`). A matching current artifact must not retrospectively prove which uncertain operation created it.

3. **High: B's source coverage gate cannot presently detect the principal truncation.** `browser_driver.py:215` truncates page text to 6000 characters before `capability/observations.py:83` computes `len(page_text) > 6000`. Thus B:49–54's `text_truncated=false` requirement can admit a clipped final “whole line.” Carry original-length/truncation metadata through the projection and bind the normalization version. Candidate-value clipping is a separate issue. Fixture ground truth should be generated independently of the parser and include whitespace, repeated lines, long values and cap boundaries; applying the identical parser twice is not an independent correctness oracle. The result proves fidelity to the declared projection, not original webpage bytes or the meaning of a financial value.

4. **High: report labels must not exceed their evidence or rewrite history.** Plan 4's timeline needs records absent from ordinary sessions: screenshots are written without observation records (`session.py:419–451`), receipts omit delivery (`:150–168`), and restarting in a reused directory removes logs but retains images (`:466–471`). A static fixture can still test presentation immediately; a factual session report must say “not recorded” and load only manifest-bound artifacts. B:86's `do.dispatched=true` is not necessarily independently established delivery; `Receipt.delivery` is explicitly separate (`receipts.py:16–18`). B:94 also leaves the completion parser's unsafe `not dispatched/refused` classification intact (`completion.py:37`). One typed evidence producer must feed both completion and report.

   B:88's recheck at report time must be an additional timestamped current-state check, never replacement of historical verification. Default rendering should be offline and repeatable from a consistent snapshot. Use bounded local artifact paths, escaped text, restrictive resource loading, and redacted observations; `script-src 'none'` alone is not an artifact-access policy. Preserve old-session uncertainty.

5. **Medium: authenticated loopback does not repair the demand argument.** B:11 asserts credentials, API absence and a 401 for a hypothetical portal; no real portal has supplied those facts. JavaScript/authentication does not intrinsically require GUI control, and Footwork's own browser route uses DevTools semantic operations (`browser_driver.py:1–15`). The fixture can show usefulness under a declared restricted tool catalog, not inevitable GUI necessity, demand, or superiority to an authorized browser/API integration. Keep it synthetic and label it accordingly. Obtain a volunteered recurring task and its ordinary method before a real-origin expansion. The 5/6 and 2/3 gates are engineering proposals, not evidence of user value.

6. **Medium: B adds more authority and runtime work than “two pieces.”** It adds source provenance, save posture, observation retention, task constraints, manifests, reporting and an authenticated fixture (B:122–170). Save needs explicit foreground authority because the current capability bridge defaults to background-only (`backend.py:94–98`; `native.py:648`; `posture.py:19–29`). B:63–68 should also record autosave/no-send outcomes durably with token replay; its stated order checks autosave before `journal.begin`. Specify new schema compatibility, permitted operations and bounded resource/time costs. Do not make task-global `job_append_exists` a universal capability restriction; confine it to the qualification recipe. The journal is generic, while the backend and recovery packet are currently append-specific (`journal.py:38–58`; `backend.py:172`).

**Order and gates:** first define these three contracts, failure scenarios and oracles together. After operation truth/identity work, qualify Finder's rename route first, Preview's transformed artifact second, and Chrome's durable event third. Each gets a bounded compatibility spike followed by a committed prediction and real-command scenarios before an installed trial. A blocked route remains a recorded unsupported case; do not silently substitute TextEdit or allow the host to perform the effect through an unrelated tool. An app-specific failure need not block qualification of the other two.

Each lane includes wrong resource, stale observation, conflicting user edit, cancellation before dispatch, lost reply after effect and repeated token cases. First qualify on an already-permitted host using disposable artifacts; retain a separate denied-permission journey. Keep budgets and denominators per lane so browser success cannot conceal a native failure. After all three pass their contracts, run **one cross-app chain**: read the transformed image's dimensions in Preview, submit those dimensions to the fixture ticket app, then use its acknowledged ticket ID to rename and move the owned PNG into an owned archive subfolder in Finder. The move is a separate next capability with source absence, exact destination, unchanged bytes and untouched sibling checks; the old `q19.py:218–223` existence-only oracle needs strengthening.

Cleanup is part of every gate: verify output before cleanup, close only the exact owned Preview document and Finder window, retire only the owned browser/listener, preserve failure artifacts, and independently confirm absence. Never force-quit Preview or Finder, clear recent items, close unrelated documents or alter global app preferences. GUI action routes and foreground scope must be declared separately from fixture setup/oracle access. This portfolio diversifies native filesystem, native visual artifact and browser transaction behavior; it still establishes technical capability, not demand or customer benefit.
